# 0009. Maps provider and fallback

Status: Proposed

## Context

Routes, ETA, place search and walking directions are needed (P1-TRIP).

## Decision

Google Maps Platform (Routes, Places) through a `maps` adapter in an Edge Function, so keys stay server-side and responses for common routes are cached. OpenStreetMap-based tiles are the fallback for map display.

Route display (P1-TRIP-01) uses the Maps Embed API: it has no per-view charge, so its key is public in the app, restricted to the web app's address and to the Embed API only. Directions (P1-TRIP-01, P1-TRIP-03) open Google Maps itself through a link, with no key and no cost. Paid calls (Routes API for travel times) stay behind the Edge Function.

## Options considered

Mapbox; OpenStreetMap only (weaker traffic data).

## Consequences

Budget alarms and API key restrictions on day one.

## Update: live map (P1-TRIP-04)

The live map uses the Maps JavaScript API for the interactive map, from the browser with the public key restricted to the web app's addresses. The road line comes from the Routes API (`computeRoutes`, without traffic: the "Essentials" price tier) through the web app's Vercel Function `api/route.ts`, because the Routes API refuses website-restricted keys (403 "The caller does not have permission" in testing). That function uses a private `GOOGLE_ROUTES_KEY` (restricted to the Routes API, set in Vercel's environment variables, never in the app), only answers for places in Ghana, and lets Vercel's edge cache share each route for a week. Each route is also kept on the phone for 7 days. The traveller's position never leaves the phone. Android shows the web page in a WebView. A daily quota on both APIs in Google Cloud caps the bill; adding live traffic would move to the Pro tier and a shorter cache.
